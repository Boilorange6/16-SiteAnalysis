# v2 P4 — 확장(일조·바람·UTCI·수관·도보권·개방감·백그라운드 실행) 구현 계획 (품질 우선 개정판)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**개정 원칙(사용자 2026-10-01):** **앱 품질이 먼저이고, 최적화는 그 안에서만 한다.** 품질을 깎아 속도를 맞추지 않는다 — 대신 백그라운드 실행·캐시·더 나은 알고리즘(그림자 다각형 래스터화, 지평선 사전계산, GPU)으로 시간을 줄인다. 품질 기준선은 sitedia 실측(`docs/research/2026-10-01-sitedia-simulation-benchmark.md`, 캡처 `docs/design/sitedia-2026-10-01/`)이며 각 기능은 그 캡처와 나란히 비교해 같거나 나아야 한다.

**Goal:** spec §6 P4 행(S03·S04·D01·D10·D26·A08·보행망)과 P3 이월(계절 4컷, D13·D14·D24 선 지물, D16 연면적, A02 배정 학교)에 더해, sitedia 대비 격차를 메운다 — 반경 전체·하루 전체 일조(S02·D21), 브라우저 WebGPU 3D LBM 바람(S03), 바람장·그늘·SVF를 결합한 UTCI(S04), 항공영상 수관 검출(D10), 도보권 등시선(D28), 개방감 SVF(D29), S01 분해 다이어그램, 계절 바람장미, 타일 단위 PNG/SVG, 공부면적, SKP(조건부). 분석은 백그라운드 작업으로 돌고 타일이 차례로 채워진다.

**Architecture:** 세 가지 공통 기반 위에 타일을 올린다. **(1) 래스터 결과 계약** — 2 m·4 m 격자 결과(일조시간, 그림자 흐름, U/U유입, UTCI, SVF, 수관)는 다각형으로 바꾸면 꼭짓점 상한(200)·면 상한(3,000) 때문에 품질이 무너진다. 그래서 `TileResult.presentation.rasters[]`(메타)와 앱 DB `tile_raster`(deflate 바이너리, 캐시 키 단위)로 저장하고, 브라우저가 팔레트로 칠해 SVG `<image>`로 지도·PPT에 넣는다(EPSG:5179 → 화면은 3점 아핀). **(2) 백그라운드 작업** — POST는 대지 확정·가벼운 타일만 동기 계산하고 202로 바로 돌아온다. 무거운 타일(S02·D21·D29·D10·S03 사례·S04)은 앱 DB `analysis_job` 큐를 `worker_threads` 작업자가 한 `EngineContext`로 순서대로 계산하고(공유 memo), 화면은 1초 폴링으로 채운다. 상태 `pending`·`running`을 계약에 더하고 캐시하지 않는다. **(3) 시뮬레이션 엔진(순수 함수, `src/lib/v2/sim/`)** — 일조 = 시간 간격마다 건물 그림자 조각(바닥·지붕 이동·변 쓸기 사각형)을 격자에 스캔라인으로 칠하고 지형은 DEM 지평선 지도(사전계산)로 가린다; SVF = 높이맵 방위 스캔; UTCI = Bröde 다항식 + 6방향 Tmrt(직달·산란·반사·장파, SVF 가중); 바람 = 브라우저 WebGPU D3Q19 LES(Smagorinsky) — 결과장을 압축해 서버에 올려 분석·계절 단위로 캐시, WebGPU가 없을 때만 엔진 D2Q9 2D 대체(명시 표기). 지형은 Copernicus GLO-30(진행 중 브랜치)이 기존 `terrain.sqlite`·`DemReader` 계약으로 들어온다.

**Tech Stack:** TypeScript, better-sqlite3 12, @turf/turf 7.3.5, proj4, zod 4, pptxgenjs 3.12, React 19 SVG, Next 15(standalone, `worker_threads`), WebGPU(WGSL, 브라우저 Web Worker), **sharp 0.34.5(승인 — 항공영상 디코딩)**, **geotiff(승인 — GLO-30, 진행 중 브랜치가 추가)**. 테스트 `node:assert/strict` + `npx tsx`, GPU 커널은 Playwright(Chrome, WebGPU 켬).

**Spec:** `docs/superpowers/specs/2026-09-29-site-analysis-v2-design.md` §3.1(외부 호출 예외: WMTS), §4.1, §4.2(A02·A08), §4.3(D01·D10·D26), §4.4(S03·S04, "GPU 미지원·취소·실패 상태를 남긴다", "부분 결과를 완료로 내보내지 않는다"), §5.3(SKP 나중), §6(P4 행). 결정 근거: sitedia 실측 비교 §3(R1~R9) — **이 계획의 사용자 결정 1~9가 R2(엔진 2D)·R9(공부면적 제외·SRTM 유지)·P3 Q6(09~15 고정)을 대체한다.** spec §4.4 "S03·S04 브라우저 계산 여부는 S03 구현 때 정한다" → S03 = 브라우저 WebGPU, S04 = 엔진(아래). spec §4.4 "S03 결과는 기준 높이·모델 의미가 호환된다고 검증한 경우에만 S04에 연결" → S04는 S03 6 m층 U/U유입 × 관측소 10 m 풍속을 "국지 10 m 등가 풍속"으로 쓰고 그 가정을 조건·한계에 기록한다(검증 근거: T24 테스트의 개활지 셀에서 비율≈1).

## Global Constraints

- **품질 우선.** 계산을 줄여 시간을 맞추는 변경(격자 굵히기, 반경 축소, 건물 상한, 시간창 축소)은 금지다. 성능은 백그라운드 실행·캐시·알고리즘으로 해결한다. 불가피한 상한(GPU 메모리 등)은 결과 `conditions.simulation`과 한계 문구에 **그대로 기록**한다. 기존 `S02_MAX_BUILDINGS = 200`·`S02_INFLUENCE_M = 300`·대지 필지만 계산은 T17에서 없앤다.
- 기존 앱 파일(`src/lib/server/**`, `src/app/site/**`, `deploy/**`, `next.config.ts`)은 수정하지 않는다. v2는 `src/lib/v2/**`, `src/components/v2/**`, `src/app/v2/**`, `src/app/api/v2/**`, `src/scripts/v2/**`만 만진다(spec §4.6). CSP(`worker-src 'self'`, `connect-src 'self'`, `img-src data: blob:`)는 WebGPU Web Worker·업로드·래스터 data URL을 이미 허용한다 — 바꾸지 않는다.
- **의존성:** `sharp`(0.34.5, 이미 next 하위로 설치됨)를 `dependencies`에 정식 추가하는 것은 승인됨 — **Judge가 G0 시작 전에 메인 체크아웃에서** `npm install sharp@0.34.5 --save-exact` 1회 실행 후 커밋한다. `geotiff`는 진행 중 브랜치 `v2-p4-glo30`이 추가한다. 실행자는 `npm install`을 실행하지 않는다(워크트리에는 `node_modules`가 없고 메인 것을 쓴다). 그 외 새 의존성 없음(WebGPU·LIC·LBM·UTCI·Dijkstra는 순수 TS/WGSL).
- **데이터 빌드·외부 다운로드·API 수집을 실행하지 않는다.** `.cache/v2/data` 아래에는 아무것도 쓰지 않는다(잠금 `.cache/v2/data/.lock`: pid 36488 `2026-10-01b` 기록이 남아 있음 — 운영자가 확인). `.cache/v2/raw`는 읽지 않는다(픽스처만). 데이터 작업은 §"데이터 운영"의 명령을 사용자/운영자가 실행한다. 테스트는 임시 디렉터리 픽스처(`engine-fixture.mjs`)와 임시 앱 DB로 한다. 예외: T15·T19의 WMTS 항공영상은 분석 시점 외부 호출 예외(spec §3.1)이며 테스트에서는 `TileDeps.fetch` 가짜로 대체한다.
- PNU·법정동 코드는 문자열. 모르는 값은 `NULL`(`missing`). `value_status`는 `observed / estimated / suppressed / missing / not_applicable`. 거리·면적은 EPSG:5179 미터(`toUtmk`). 구간은 하한 포함·상한 제외, 마지막 구간 상한 개방.
- **시뮬레이션은 탐색·근사다.** S02 "법정 일조권 검토가 아님", S03 "조기설계 참고용 — 풍동·검증 CFD 아님, 주풍향 1방향 입력, 보행 안전·인허가 판단에 쓰지 않음", S04 "현장 측정·개인별 건강 위험 예측이 아님 — 숫자를 인용하지 말고 자리끼리 비교"를 그대로 적는다. S03 지표는 상대풍속 `U/U유입`만(m/s 지표 없음). UTCI 풍속 적용 범위 0.5~17 m/s 밖은 **자르지 않고** `utci_out_of_range` 범주·면적률로 낸다.
- 직선거리를 도보 n분으로 환산하지 않는다. 도보 시간·도달 면은 **보행망 라우팅 결과에만** 붙이고 "보행망 도보(OSM, 80 m/분, 내부 제안 기준)"를 명시한다. 등급(좋음·보통·주의)은 spec §4.1대로 직선거리에만 매긴다.
- D 타일 공통 규칙(P3과 같음): 파일 하나(`tiles/dXX.ts`)와 테스트 하나만 소유, 원천 없으면 `notProvided`, coverage `partial/incomplete`면 `partial`, 뒷면 `share_*`(%)·`back_*`(개수), 채움률 `fill_*`, 판단 `{ level: null, criteria: null }`, 문장은 사실 → 의미 → 확인할 것, 테스트 끝에 `assert.doesNotMatch(JSON.stringify(view), /종합|법적 적합|개발 가능|건강 위험 예측/)`.

## Review Focus

1. **시뮬레이션 수치가 실측처럼 새는 경로** — S03 지표 단위에 `m/s` 없음(`assert.ok(!metrics.some(m => m.unit === "m/s"))`), S04 범위 밖 셀은 `utci_out_of_range`로 분리하고 중앙값에서 뺀다(풍속을 0.5로 올리거나 17로 내리는 분기 없음). 문장에 "안전"·"CFD 동등"·"건강 위험 예측" 없음. (T22·T24 테스트)
2. **브라우저 업로드(신뢰 경계)** — 바람장 업로드는 로그인·분석 소유자만, 본문 상한(40 MB)·해제 후 크기·격자 차원·값 범위를 zod와 길이로 검증하고, 캐시는 **올린 사용자 범위**(캐시 키에 userId)로만 재사용한다. 결과 출처에 `computedBy: "browser-webgpu"`·어댑터 이름을 남긴다. (T22 테스트: 남의 분석 403, 차원 불일치 400, 41 MB 413, 다른 사용자 같은 대지 → 재사용 안 됨)
3. **부분·대기 결과가 완료로 나가는 경로** — `pending`/`running`은 캐시 제외·PPT 상태 장, S03은 계산된 계절만 `seasons`에 넣고 빠진 계절은 슬라이드 컷에서 선택 불가, S04는 바람장 없는 계절을 `pending`으로 남긴다. (T1·T3·T22·T24 테스트)
4. **래스터 위치 정합** — EPSG:5179 격자 → 웹 메르카토르 화면 아핀 변환이 반경 1 km 끝에서 1 px(1200 px 그림) 이내, 같은 타일의 벡터(건물 폴리곤)와 래스터가 겹친다. (T2 테스트: 격자 모서리 3점 + 중심의 투영 오차)
5. **직선거리와 보행거리 혼합** — 등급 `grades[].metricId`가 `walk_`로 시작하지 않음, 보행망 없으면 `walk_*` missing·문장에 "도보" 없음. (T25·T26 테스트)
6. **검출·가정이 사실처럼 보이는 경로** — D10은 "항공사진 색 기반 수관 검출 · 재현율 미검증"을, S04는 "수목 높이 8 m 가정"·"S03 6 m층 비율 × 관측소 10 m 풍속"을 조건과 한계에 적는다. (T19·T24 테스트)
7. **옛 데이터 파일** — `weather_season_hour`·`wind_rose_season`·`renewal`·`landuse`가 없는 파일에서 S04·D22 계절·A08 신규갱신·D10 OSM 보조층이 `notProvided`/`missing`으로 간다. (T4·T5·T21·T24·T27 테스트: 열/테이블 없는 픽스처)
