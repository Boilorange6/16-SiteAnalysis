# v2 P1c-0 — 타일 보드 화면 뼈대 (예시 결과로 먼저)

**목표:** 데이터 적재·분석 엔진(P1b)을 기다리지 않고, P0의 `TileResult` 계약만 입력으로 받는 타일 보드 화면을 `/site/v2`에 만든다. 예시 결과(fixture)로 동작하며, 나중에 P1b 결과로 교체할 때 화면 코드는 바뀌지 않아야 한다.

**근거:** 스펙 `docs/superpowers/specs/2026-09-29-site-analysis-v2-design.md` §2·§4·§5, 타일 카탈로그 `docs/research/2026-09-29-tile-catalog-astra.md`, 시안 `docs/design/alt4/A4-*.dc.html`(+같은 이름 `.png` 캡처), 디자인 검토 결과(아래 "화면 규칙").

**범위 밖(이번에 만들지 않음):** 3D 시뮬레이션 계산·재생, PPT/PNG 출력, 한 판 인쇄, 레이어 스택, 모바일 전용 조작, 주소 검색·필지 선택(시작 화면), 저장·다시 열기, 로그인 연동(예시 데이터만 쓰므로 P1b 연결 때 추가).

## 화면 규칙 (검토 결과, 필수)

1. **종합 점수 없음.** 왼쪽 위 큰 칸은 "대지 요약": 주소, 면적㎡, 용도지역, 반경, 사실 3줄, 자료 기준일, 불완전 배지.
2. **도보 n분 금지.** 거리 지표는 `"480m"` + 보조어 `"직선"`. 어떤 문자열에도 `도보`, 숫자 뒤 `분`이 나오지 않는다.
3. **학교:** "통학구역 안(학구도 기준일)"과 "배정은 교육청 확인"을 분리해 표시. "배정 ○○초" 같은 확정 문구 금지.
4. **공급·가격·개발은 좋음/주의로 평가하지 않는다.** `judgment.level`은 거리 지표 타일(A01·A02)에서만 쓰고, 등급 옆에 `criteria`를 "내부 제안 기준: …"으로 붙인다.
5. **상태 배지** (`TileView.badges`, 같은 의미를 타일·상세에서 동일하게):
   - 타일 `status`: `partial`→"일부 자료만 집계", `failed`→"계산 실패", `cancelled`→"취소됨", `no_data`→"자료 없음", `not_provided`→"다음 단계에서 제공".
   - `limitations[].kind`: `estimated`→"추정", `incomplete`→"지역 자료 불완전", `partial`→"일부 자료만 집계", `unknown`→"미확인", `suppressed`→"비공개", `not_provided`→"자료 미확보". 배지 툴팁/상세에 `note` 원문.
   - 지표 `status`: `missing`→값 대신 "미확인", `suppressed`→"비공개", `not_applicable`→"해당 없음", `estimated`→값 + "추정". 값 0인 `observed`는 "0"(확인된 0건)으로 그대로 보여 준다.
   - 중복 가능(A06): limitation note에 따라 "중복 가능 · 합계 보류" 배지를 띄우고, 합계 지표 대신 원천별 지표를 줄로 보여 준다.
   - 모델 한계: S02 → "그림자 추정 · 법적 판정 아님", S03 → "탐색용" 배지를 **항상** 표시(상태와 무관).
6. **출처 줄:** 모든 타일 맨 아래 `sourceLine` = 원천별 `sourceId sourceAsOf`를 " · "로 연결. `sourceAsOf`가 null이면 "기준일 미확인". 원천이 없으면 "출처 없음".
7. **판단 문장:** `judgment.sentence`를 그대로 쓰되 fixture는 "사실 → 의미 → 확인할 것" 형식으로 작성(예: "인접 구역에 3종일반·상업 → 용도가 섞인 지역 → 지구단위계획 확인 필요").
8. **도판(D04):** 앞면=도판, 뒤집기=구성비(보기만 전환). 별도 선택 "보고서 출력: 도판/구성비/둘 다" → `board-state`의 `outputFace` 저장, 타일에 배지로 표시.
9. **조작:** 모든 타일에 같은 자리 `펼치기` · `보고서` 체크(라벨에 타일명 포함, 예 aria-label "교통 보고서 포함"). 편집 모드: 제거(×) 후 "삭제됨 · 되돌리기" 알림, 위/아래 이동 버튼(끌기는 선택 사항), "완료".
10. **분석 중 데모:** 버튼 하나로 타일이 0.3초 간격으로 차례로 채워지는 상태(대기→계산 중→완료/실패)를 재생. 실패 타일은 "이 타일 다시 계산" 버튼(데모에선 성공으로 바뀜). 상단 진행 "7 / 10".
11. **보고서 장수:** 상단 버튼 "보고서 만들기 · N장", 옆 설명 "표지 1 + 타일 n" (출력 면 `both`인 도판은 2장). 버튼은 이번엔 비활성 + "P1c 다음 단계" 툴팁.
12. **스타일:** Alt4 시안 값을 따른다 — 배경 #EEF0F3, 타일 흰색 radius 18px padding 16/18, 제목 14px 700 + 색 점 10px, 큰 숫자 Do Hyeon(`next/font/google`의 `Do_Hyeon`) 38px, 본문 Noto Sans KR(루트 레이아웃 변수 재사용), 보조 글자 #676C76, pill 버튼. 격자: 데스크톱 4열(대지 요약 2×2), 900px 이하 2열, 520px 이하 1열. 페이지 가로 스크롤 금지.
13. **접근성:** 버튼은 `<button>`, 상세는 `role="dialog"` + Esc 닫기 + 초점 복귀, 선택 상태는 `aria-pressed`/`aria-checked`, 진행은 `role="progressbar"`.

## 작업 순서 (TDD)

1. `tile-catalog.ts`, fixture 10개 작성 → 테스트: 모든 fixture가 `parseTileResult` 통과, 코드 10종 존재, 상태 다양성(complete·partial·failed·not_provided 각 1개 이상, `incomplete`·`estimated` limitation 각 1개 이상, `observed` 값 0 지표 1개 이상).
2. `tile-view.ts` → 테스트: 규칙 2(모든 fixture 뷰의 모든 문자열에 `/도보|\d\s*분/` 없음), 규칙 1(`종합` 없음), 3(A02에 "배정은 교육청 확인" 포함, `/배정\s+\S+초/` 없음), 4(A05·A06·A07·A09 뷰에 등급 없음), 5 매핑 표 전부, 6(null 기준일→"기준일 미확인"), S02·S03 고정 배지.
3. `board-state.ts` → 테스트: 제거→되돌리기 복원(순서 포함), 위/아래 경계, 보고서 체크, outputFace, 장수 계산(표지 1 + 포함 타일, both=2).
4. 컴포넌트·페이지. 테스트는 순수 함수에 두고 컴포넌트엔 로직을 두지 않는다.
5. 검증:
   - `npm run test:v2` 전부 통과, `npm run lint`(tsc) 통과, `npm run build` 통과.
   - dev 서버(`npx next dev -p 3107`)에서 Playwright(channel "chrome")로 `http://localhost:3107/site/v2` 캡처: 1440×900 보드, 편집 모드, 상세 열림, 분석 중 데모 중간, 390×844 모바일. `document.documentElement.scrollWidth <= innerWidth` 확인. 콘솔 에러 0.
   - 캡처는 `docs/design/p1c0/`에 저장(커밋 대상).
