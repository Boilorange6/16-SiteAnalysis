## 알려진 공백과 사용자 조치

1. **6개 시도 연속지적도 수동 다운로드 (가장 큰 효과).** 경기·충남·경북·경남·전남광주·전북은 건물 중심으로 대신해서 건물이 없는 필지와 대단지 필지 일부가 위치를 못 얻는다. 예: 다산 — 검수 좌표(37.6245, 127.1506)는 OSM 다산역(37.6243, 127.1498)과 같고, 반경 1/2/3 km 공동주택은 1/167/524. 역 주변 진건지구 단지가 위치 미확인이다(다산동 총괄표제부 단지 72개 중 35개만 위치 확보). PC에서 VWorld 로그인 → 연속지적도형정보(dsId 23) → 해당 시도 선택다운로드(라온K 설치) → `.cache/v2/raw/cadastral/<기준일>/<시도>.zip` → `npm run data:build -- --version <새 이름>`.
2. **대안(자동화):** VWorld API 인증키로 위치 미확인 PNU만 적재 시점에 조회해 채우기 — 인증키 발급은 사용자가 VWorld에서.
3. **블록 지번(신도시):** 대지_구분_코드 2는 PNU가 없어 위치 미확인(세종 행복도시 등) → P2(GIS건물·도로명 건물).
4. **다음 재빌드 주의:** 지적도 6개 시도가 더해지면 `parcel` 지역·건수가 늘어 검사를 통과한다. 일부만 더하면 `parcel_building`의 지역이 줄어 REGION_MISSING이 날 수 있다 — 그때는 `--reset-baseline parcel_building`.

## P1b가 먼저 알아야 할 것

- `planned_supply`는 청약홈과 입주예정을 원천별로 그대로 넣었다(같은 사업 중복 가능). `properties.source`로 나누고 A06에서 중복을 정리한다. `project_id = event_id`.
- `housing_complex`의 총괄표제부 행에는 세대가 있는 단독주택(다가구)도 있다. `properties.mainUse`로 나눈다.
- 위 6개 시도의 A05·A06 수치는 지적도가 들어오기 전까지 불완전으로 표시한다.
- `byRegion` 키는 원천마다 다르다(결과 문서의 표).

## P1a-2로 넘김

- 실거래(RTMS)·정비사업·계획/운영 철도·OSM PBF·K-APT 적재.
- `quality-gate.ts`의 totalCount 비교를 `received` 기준으로 정리(현재 적재 틀만 received로 비교).
- 원천이 파일 종류를 옮길 때 급감 검사 공백, 게시 전 무결성·FK·R*Tree 검사(spec §3.4 2단계), content-encoding 응답의 길이 비교.
- 작은 정리: "baseline reset" 로그 중복, CLI가 `oldestDate` 대신 자체 함수 사용, 잘못 적은 `--reset-baseline` id 경고 없음.
