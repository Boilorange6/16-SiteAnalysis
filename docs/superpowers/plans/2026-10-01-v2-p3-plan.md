# v2 P3 — 3D·지형·기상 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 지형(DEM)과 기상(ASOS 풍향·풍속)을 로컬 데이터 파일로 적재하고, spec §6 P3 행의 산출물 — 3DM 내보내기, S02 일조·그림자 확장과 D21 일조시간, D15 가구·D16 밀도·D17 지형·D18 경사, D22 바람장미, S01 지형 반영 — 과 P2에서 이월한 S01 카메라 UI(Q9)·GLB 세부(Q7)를 만든다. v1(P2) 기준을 깨지 않는다: 모든 타일은 `TileResult` 계약, 내보내기는 저장된 `Scene`에서만, 외부 호출 0.

**Architecture:** DEM은 AWS Terrain Tiles(Skadi `.hgt`, SRTM 1″ ≈ 30 m, 지표고·EGM96)를 새 데이터 파일 `terrain.sqlite`(`dem_row` 행 BLOB)에 넣고 `DemReader`가 행 단위로 읽는다(GeoTIFF 리더·의존성 없음, 기존 manifest·GC·잠금 틀 그대로). 기상은 기상청 ASOS 시간자료를 풍향 16방위 × 풍속 5구간 빈도로 집계해 `weather.sqlite`에 둔다. 격자형 도판(D16·D17·D18·D21)은 공통 도우미 `raster-grid.ts`(로컬 격자 → `@turf/isobands`·`isolines` → 반경 절단 면·선)로 만든다. 장면(`Scene`)은 v2로 올려 지반 격자와 건물 바닥 높이를 담고, S01 그림·DXF·GLB·3DM이 같은 장면을 쓴다. 지도 계약에 선 지물(`MapLine`)을 더해 등고선을 그린다. 화면·보고서는 P2와 같이 보드 상태(순수 reducer)와 슬라이드 계획의 확장이다.

**Tech Stack:** TypeScript, better-sqlite3 12, @turf/turf 7.3.5(`isobands`·`isolines`·`polygonize`·`lineSplit` 포함 — 메인 체크아웃 `node_modules/@turf` 확인), proj4, zod 4, pptxgenjs 3.12, React 19 SVG, earcut(전이 의존성), **rhino3dm(신규 — open Q3 승인 후 사용자가 설치)**, 테스트 `node:assert/strict` + `npx tsx`.

**Spec:** `docs/superpowers/specs/2026-09-29-site-analysis-v2-design.md` §3.2(dem·epw 파일), §4.3(D15~D18·D21·D22), §4.4(S01·S02 장면·컷), §5.1·§5.3(3DM), §6(P3 행), §7(DEM·DSM, 기상 입력). 범례·구간 근거: `docs/research/2026-09-29-tile-catalog-astra.md` §4.3·§5. 원천 권리: `docs/superpowers/a0/2026-09-29-a0-verification.md` #20(dem ✅)·#21(weather ⚠️ EPW, ASOS ✅). 충돌 시 spec을 따른다.

## Global Constraints

- 기존 앱 파일(`src/lib/server/**`, `src/app/site/**`, `deploy/**`)은 수정하지 않는다. v2는 `src/lib/v2/**`, `src/components/v2/**`, `src/app/v2/**`, `src/app/api/v2/**`, `src/scripts/v2/**`만 만진다(spec §4.6).
- 새 npm 의존성은 **rhino3dm 하나**(open Q3)뿐이고 설치는 사용자가 메인 체크아웃에서 한다. 실행자는 `npm install`을 실행하지 않는다. 워크트리에는 `node_modules`가 없고 메인 체크아웃 것을 쓴다. T11은 `import("rhino3dm")`이 실패하면 BLOCKED로 보고한다.
- **데이터 빌드·외부 다운로드를 실행하지 않는다.** `.cache/v2/data/.lock`을 buildings 빌드(pid 36488, 버전 `2026-10-01b`)가 쥐고 있고 parcels(`2026-10-01c`, 약 33 GB)가 뒤에 대기한다. 데이터 작업은 §"데이터 운영"의 명령을 **사용자/운영자**가 실행한다. 테스트는 모두 임시 디렉터리 픽스처(`engine-fixture.mjs`)로 한다. `.cache/v2/data` 아래에는 아무것도 쓰지 않는다.
- PNU·법정동 코드는 문자열. 모르는 값은 `NULL`(`missing`). `value_status`는 `observed / estimated / suppressed / missing / not_applicable`.
- 거리·면적은 EPSG:5179 미터(`toUtmk`). 구간은 하한 포함·상한 제외, 마지막 구간 상한 개방(spec §4.3). 격자형 도판은 격자 셀 중심이 원 안에 있는 셀을 분모로 하고, 면은 `areaInCircle`로 절단한 교차 면적을 분자로 쓴다.
- **DEM은 지표고(DEM)이지 표면고(DSM)가 아니며** 수직 기준은 EGM96, 해상도 1″(약 30 m)다. 모든 지형 산출물(D17·D18·S01·DXF·GLB·3DM·장면)에 `resolutionM: 30`, `vertical: "EGM96"`을 기록하고 "30 m 격자 보간 — 측량값 아님"을 한계로 남긴다(spec §7). 보간 결과를 원본보다 정밀한 것처럼 표시하지 않는다.
- 높이 미상 건물은 지형 위에서도 바닥 모양만 둔다(z = baseZ). 층수·미터를 서로 환산하지 않는다. `floors_estimate` 높이는 `[추정]` 분리 유지.

## Review Focus

1. **DEM 결측·경계가 0 m로 스며드는 경로** — `dem_row` 값 −32768(void)·타일 없음은 `null`이고 D17·D18은 `dem_nodata`/`slope_nodata` 범주로 센다. 장면 지반 격자의 결측 셀은 이웃 보간이 아니라 `null`(GLB·3DM에서 그 셀 삼각형 생략). (T3·T7·T14·T15 테스트)
2. **지형 위 건물의 바닥·높이 혼동** — `baseZ`는 발자국 대표점의 지표고(원점 상대)이고 건물 높이는 그 위에 더한다. 미상은 바닥만. DXF `38`, GLB·3DM 벽 아래쪽 = baseZ. (T7·T9·T10·T11 테스트)
3. **S02 수광면과 영향 영역** — 필지 도형이 있으면 그 외곽을, 없으면 60×60 m 박스를 수광면으로 쓰고 조건에 `site: "parcel"|"box"`를 적는다. 미계산 셀은 D21 분모에서 빠지고 0시간에 들어가지 않는다. 09·12·15 그림자는 10분 누적 계산을 대신하지 않는다. (T12·T13 테스트)
4. **블록·밀도의 가짜 경계** — D15는 반경 밖 500 m까지 도로를 읽어 폐합을 계산하고 읽기 범위 경계에 닿는 면은 `block_open`(미폐합)이다. 원을 도로처럼 쓰지 않는다. D16은 반경 밖 300 m 건물을 입력에 넣어 경계 저하를 줄인다. (T16·T17 테스트)
5. **보고서가 보드 상태를 잃는 경로** — S01 카메라 프리셋·S02 컷 수는 `board_json`에 저장되고 PPT는 그 값을 쓴다(화면에서 잠깐 돌려본 카메라는 저장 전까지 반영 안 됨, spec §5.1). (T19·T21 테스트)
