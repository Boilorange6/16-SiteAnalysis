# v2 지도 확대·이동(줌·팬) 계획 — 33개 타일 리뷰 통합

라인 번호는 리뷰 시점 기준 — 구현 전 재확인

- 범위: 보드 카드(MapBox), 펼침 TileDialog(Stage frame=detail), 상세 DetailWindow(DETAIL_CODES 26개), A05·A06 CalloutMap.
- 원칙: 분석은 다시 돌리지 않는다. 화면만 다시 그린다. 품질이 먼저다. 그래서 CSS 늘리기 대신 **뷰포트를 바꿔 다시 그린다**.
- 근거: 리뷰 7건(공용 레이어, G1~G6). 디자인 언어(`docs/design/v2-design-language.md`) §1·§5·§6·§8·§9를 따른다. 새 패턴(지도 위 조작 버튼)은 §5 사용자 결정 1·2를 거쳐 디자인 언어 문서에 추가한다.

## 1. 공통 규칙

| 규칙 | 채택안 | 이유(리뷰 근거) |
|---|---|---|
| 줌 방식 | **하이브리드.** 제스처 중에는 지도 레이어에 CSS transform으로 미리 보여 준다. 손을 떼거나 휠이 150 ms 멈추면 `view={zoomDelta, offsetM:[동,북 m]}`를 확정한다. 그다음 `applyView(framedViewport(...))`로 다시 그린다. | 뷰포트를 바꾸면 벡터·배경 타일 z·래스터 아핀·축척·클릭 역변환·대지 표식 모드가 한 번에 맞는다(map-figure.tsx:414-424, 543-559). CSS만 쓰면 흐려지고 글자와 범례가 커진다(detail-window.tsx:449, 465). 프레임마다 다시 그리면 D05 3,000동, D29 약 3003² PNG에서 끊길 수 있다(공용·G5). 그래서 확정할 때만 다시 그린다. |
| 최대 줌 | `maxZoom = min(baseZoom + maxDelta, maxAbsZoom ?? 19)`. 기본 `maxDelta=3`(×8). 절대 상한은 19다(MAX_TILE_ZOOM, map-projection.ts:4). 19.5~20 업스케일은 허용하지 않는다(사용자 결정 8). 래스터가 켜져 있으면 셀 1개가 화면 **12 px**를 넘지 않도록 상한을 더 낮춘다. | 리뷰마다 단위가 달랐다. 상대 배수(G1·G2·G3)와 절대 z(G4·G5·G6)를 이 식 하나로 모두 표현한다. z19를 넘으면 배경 타일이 흐려진다(G4 D01). 래스터 기준은 공용 리뷰 24 px와 G5 8~12 px가 충돌했다. G5 값을 채택한다. 24 px면 S02 6 m 셀이 z19까지 커져 없는 정밀도를 보여 준다. 이 규칙 때문에 S03은 G6 제안 z19가 아니라 약 z18.5가 된다. |
| 타일별 값 위치 | `tile-catalog.ts`에 선택 필드 `mapZoom?: {maxDelta?, maxAbsZoom?, card?}`를 둔다. | 공용 리뷰안을 채택한다. TileClientModule 안(G1·G2)보다 데이터 한 곳에 모으는 편이 낫고, 공용 코드에 타일 분기가 생기지 않는다. |
| 이동 제한 | 화면 중심이 반경 원 안에 있어야 한다(`|offsetM| ≤ radiusM`). 반경 밖은 지금처럼 clip과 어둡게 덮기를 유지한다. | 33개 타일 모두 자료가 반경 안에서만 만들어지거나 원으로 잘린다(map-figure.tsx:897 등). G3의 "원 일부만 남기기"는 빈 화면을 허용하므로 쓰지 않는다. D05의 "표시 한계 거리 제한"은 엔진 출력을 바꿔야 해서(재분석) 쓰지 않는다. |
| 휠·핀치 | **카드**: 버튼, Ctrl/⌘+휠, 두 손가락 핀치·이동만 받는다. 일반 휠과 한 손가락은 보드 스크롤로 넘긴다. **펼침·상세**: 일반 휠로 확대하고 한 손가락으로 이동한다(`touch-action:none`). 휠은 `addEventListener('wheel',…,{passive:false})`로 붙인다. 확대 기준점은 커서 위치다. | 모든 그룹이 같은 결론이다(보드 스크롤과 충돌). React onWheel은 passive라 preventDefault가 듣지 않는다(detail-window.tsx:411-412, map-legend-strip.tsx:187-201 선례). |
| 클릭과 드래그 구분 | 지물 위에서도 드래그를 시작할 수 있다. 4 px 이상 움직였으면 뒤따르는 click을 모두 버린다. 대상은 지물 고정, mapClick, 카드 펼침(onOpen), 설명선 점·카드, `/detail/<code>/at` 조회다. 드래그 중에는 hover 라벨을 갱신하지 않는다. | D05·D17·D18·D28처럼 지물이 화면을 덮는 타일에서는 지금 이동이 불가능하다(detail-window.tsx:418). 드래그 뒤 click이 카드를 펼친다(tile-card.tsx:382, 808-809). suppressMapClickRef 패턴을 재사용한다(detail-window.tsx:395-398, 432). |
| 키보드 | 지도에 초점이 있을 때 `+`/`−`/`0`(초기화). 방향키로 이동하지 않는다. Esc는 지금처럼 라벨 해제다. | A05·A06의 ←/→ 페이지 넘김과 겹친다(callout-map.tsx:270-278). |
| 초기화 UI | 공용 조작 묶음은 `＋`, `−`, `시점 초기화` 버튼이다. 기존 detail-window 버튼(:486-491)을 옮겨 공용으로 쓴다. S01과 같은 문구와 힌트 줄을 쓴다(mass-3d.tsx:311-319). aria는 "지도 확대"·"지도 축소"·"지도 시점 초기화"다. 버튼은 시각 32 px, 누름 영역 44 px다(디자인 §5). `시점 초기화`는 기본 상태가 아닐 때(`!isDefault`)만 보인다. 상세 창의 전체화면 버튼은 그대로 둔다. | 공용·G6 S01 리뷰. 호버 전용 금지(디자인 §1). 카드 위치는 사용자 결정 2. |
| 라벨 재배치 | 확정 렌더 때 다시 배치한다. 자동 라벨 후보는 화면(W×H) 안의 것만 남긴다. 선 라벨 앵커(map-figure.tsx:623 가운데 점)와 면 라벨 앵커는 화면과 겹치는 부분에서 다시 고른다. 같은 문구는 한 번만 낸다(디자인 §8). 우선순위 0을 확대 때 올리는 일은 이번에 하지 않는다(사용자 결정 7). | G3 D12·D13·A12에서 확대·이동하면 보이는 지물에 이름이 사라진다. 승격은 디자인 §8 계약을 바꾸는 일이다. |
| 상한 표기 | `표시 N / 전체 M` 주석(map-figure.tsx:287)은 확대 중에도 보인다. 줌으로 자료를 더 불러오지 않는다. | G1·G4·공용. 상한 방식을 바꾸는 일은 재분석이 필요하다(사용자 결정 6). |
| 래스터 보간 | `imageRendering`을 `ref.kind` 대신 해석된 팔레트 모드로 정한다. `continuous`만 `auto`이고 stepped·class·mask는 `pixelated`다(map-figure.tsx:891). | S02·S04는 scalar이면서 stepped라서, 확대하면 범례에 없는 중간색이 생긴다(G5·G6, high). |
| 배경 타일 전환 | 확정 렌더로 z가 바뀌면 새 타일을 다 받을 때까지 이전 z 타일을 아래에 남긴다. 지금은 key에 z가 들어 있어 바로 사라진다(map-figure.tsx:870). | 품질 우선(흰 깜빡임 제거). 요청은 확정할 때만 보내므로 프록시 버킷(초당 50, 순간 200) 부담도 준다(G4 D01). |
| 내보내기 | PNG·SVG·PPT·컷 시트(S03·S04 2×2·3×1)는 view를 받지 않는다. 항상 줌 없는 framedViewport로 그린다. | 모든 그룹이 같다. 범례 강조처럼 "화면 탐색용"으로 본다(디자인 §7). "화면 = 보고서" 원칙과의 관계는 사용자 결정 4. |
| 상태 수명 | `view`는 TileCard 로컬 state다. 뒤집기, 레이어 옵션(A01·A02·A04), 계절·시각·높이 컷(S02·S03·S04), rasterHrefs 재디코드에도 **유지**한다. model 정체성이나 mapKey에 묶지 않는다. 사이트·반경·분석 결과가 바뀌거나 언마운트되면 초기화한다. 펼침은 0에서 시작한다(사용자 결정 3). board-state undo와 저장에는 넣지 않는다. 편집 모드와 계산 대기·진행(state) 중에는 조작을 끈다. | 공용 (a)안. G5·G6은 계절·컷 비교에서 같은 화면을 요구한다. G3의 "뒤집으면 초기화"에는 근거가 없어서 유지 쪽으로 정한다. 오프셋을 미터로 두므로 카드 크기가 바뀌어도 같은 장소다. |
| 제외 | S01(3D, 자체 조작), D22(바람장미). 카드에서만 끄는 타일은 A05·A06이다(설명선 배치 비용과 충돌, 펼침·상세에서는 켠다). | G6·공용·G2. |

## 2. 공통 변경

### 2-1. 합친 요청(sharedRequests 통합)
1. **map-projection.ts**: 순수 함수 `applyView(vp, lat, view?)`, `clampView(view, radiusM, maxZoom)`, `maxZoomFor(base, mapZoom, rasterCellM?)`를 추가한다. 위도 역변환은 framedViewport(:36-41)와 같은 방식으로 한다. assert 자가 점검을 둔다. 확인할 것: view 없음 또는 0이면 결과가 같다, 미터 오프셋을 왕복해도 같다, 상한 식이 맞다. (공용 #1, G1·G2·G3·G4·G5·G6의 상한·이동 제한 요청)
2. **map-figure.tsx**: 선택 prop `view?`·`dragging?`을 받는다. `:414 vp = applyView(...)`. dragging이면 hover를 막는다. 래스터 보간을 모드 기준으로 바꾼다. 라벨 후보를 화면 안으로 거르고 앵커를 다시 고른다. 이전 z 배경을 유지한다. view가 없으면 출력이 지금과 같아야 한다(내보내기 하위 호환).
3. **use-map-view.ts(신규) + 조작 버튼 컴포넌트**: `useMapView({radiusM, maxZoom, wheel:'plain'|'modifier'|'off', touchPan:'one'|'two'})`가 `{view, previewTransform, dragging, bind, reset, zoomBy, isDefault}`를 돌려준다. 네이티브 wheel은 passive:false로 붙인다. 4 px 임계로 click을 억제한다. 150 ms 뒤 확정한다.
4. **map-box.tsx**: view를 MapFigure로 넘긴다. 항공 결손 탐지 vp(:156)와 축척 칩 vp(:230)도 applyView를 거친다. 활성 래스터 cellM을 maxZoomFor에 넘긴다.
5. **callout-scene.ts + callout-map.tsx**: `calloutScene(..., view?)` :46과 축척(:305-311)과 배경 MapFigure(:318)에 같은 view를 넘긴다. 제스처 중에는 지시선을 숨기고 카드 배치를 고정한다. 확정되면 다시 배치하고, 화면 밖 점은 번호 점·카드에서 뺀다. 점·카드 click도 억제한다.
6. **detail-window.tsx**: CSS transform 줌(:240-241, 402-435, 449, 465, 486-491)을 훅과 view로 바꾼다. :418 지물 위 차단을 없앤다(4 px 규칙). 상한은 maxZoom이다. D22는 maxDelta 0이라 조작이 없다.
7. **tile-card.tsx + tile-dialog.tsx(+ StageProps/TileStageProps)**: view와 onView를 통과시킨다. 카드는 휠을 modifier로, 터치는 두 손가락으로 받는다. 드래그 뒤 onOpen(:808-809)을 억제한다. 편집 모드, `state`(:275), `mapZoom.card=false`에서는 끈다. 펼침은 plain 휠과 한 손가락이다.
8. **tile-catalog.ts**: `mapZoom` 필드와 §3 표의 값을 넣는다.
9. **변경하지 않음**: `export/tile-image.ts`, `report/map-image.ts`, 컷 시트.

### 2-2. 충돌 판정
| 충돌 | 판정 | 이유 |

| rasterAffine 기준점을 화면 기준으로 다시 잡기(G5, 추정) | W0에서 측정하고, 1 px를 넘을 때만 W1에 넣는다. | 근거가 "추정"뿐이다. |
| 상한 정책(capPolygons 최근접 순 등, G3·G4) | 이번 범위에서 뺀다. 측정 후 사용자 결정 6. | 엔진 출력이 바뀌어 재분석이 필요하다. |
| 라벨 승격(G3) | 이번 범위에서 뺀다(사용자 결정 7). | 디자인 §8 계약을 바꾼다. |

## 4. 웨이브

### W0 확인(읽기·측정, 코드 변경 없음)
1. rasterAffine 잔차: 반경 3 km 대지에서 D29·S02를 z19로 놓고 벡터 건물과 몇 px 어긋나는지 잰다. 1 px를 넘으면 W1 #2에 기준점 재설정을 넣는다.
2. 상한 실측: 반경 1·2·3 km에서 D19·D02·D03·D04 polygonsTotal, D13 linesTotal, A03·A05 featuresTotal을 잰다(결정 6의 근거).
3. D10 반 셀: canopy-shared.ts:168-170 모서리 규약과 raster-image.ts:95-98을 대조해 확정한다.
4. detail-window의 React onWheel이 경고를 내는지, 모달 바깥이 스크롤되는지 확인한다.
5. `/detail/<code>/at`가 반경 밖 좌표를 받았을 때 어떻게 답하는지 확인한다(이동 제한 뒤에도 원 안 가장자리 클릭은 가능하다).
6. S03·S04 mapKey(cut.ts:70)와 A01 레이어 필터가 MapBox를 다시 마운트하는지 확인한다. 상태를 TileCard에 두면 유지되는지 본다.
7. VWorld 위성 z19가 서울과 지방에서 제공되는지 확인한다.

### W1 공통(한 담당자, 차례로)
§2-3 순서대로 진행한다. 각 단계 뒤 `tsc`와 해당 단위 점검을 돌린다. 내보내기 PNG가 바이트 단위로 같은지 비교한다(view 없음).
