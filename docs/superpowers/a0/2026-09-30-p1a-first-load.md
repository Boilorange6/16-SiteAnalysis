## 문제와 후속

1. (해소) 대용량 시도 지적도 6곳은 `npm run vworld:fetch-large`로 받아 실제 지적도로 교체했다. 건물 대체는 제거.
2. 전북 시군구 이름이 원천 그대로 "전북특별차지도 …"(오기), 제주는 "제주도 …"로 나온다. `resolveJibunAddress`가 SIG 이름의 시도 접두어를 별칭 표로 정규화하도록 고쳤다(테스트 포함).
3. 위치 확보율(d): 대장 총괄 98.5%, 표제부 98.6%, 오피스텔 99.3%. 남은 미확인은 블록·롯트(PNU 없음, 신도시)와 PNU를 못 만드는 지번이다. 신도시 블록 지번은 P2 이월. 전북(52)은 지적도가 500 MB 초과(목록상 588 MB)라 일반 다운로드가 `HTTP 200 — 세션 만료이거나 대용량 전용 다운로더가 필요한 파일`(NOT_A_FILE)로 실패했다. 강원은 첫 시도에서 `terminated`(연결 끊김)였고 재시도로 받았다.
4. 입주예정 77.2%(c: 57.2%): 지번 0-0 등으로 PNU를 못 만드는 행이 많다(Task 10 실측과 같은 원인).
5. 소요 시간: 네 번째 빌드(d)는 238.5분(지적도 3,987만 필지 + 상가 277만 건). 세 번째(c)는 169분(파트 전체 + 상가 277만 건). 적재 최적화는 P1a-2 후보.
6. 표제부 `title_202608.zip`은 헤더 없는 `|` 구분 txt(8,064,406행, 77열)라서 A0 측정 JSON의 `fields`로 헤더를 붙인 쉼표 CSV `title_202608.csv`로 변환해 사용했다.
7. 경북 GIS건물은 첫 두 번 `terminated`로 끊겼고 세 번째에 받았다(재시도 필요할 수 있음).

## P1b 인터페이스 메모

- **planned_supply**는 청약홈(`props.source = "applyhome"`)과 입주예정(`"move_in"`) 레코드가 섞여 있고, 같은 사업이 양쪽에 있을 수 있다. 소비 쪽에서 `props.source`로 나누거나 중복을 제거해야 한다. 사업 식별은 `development_event.project_id`(= `event_id`)를 쓴다.
- **housing_complex**(총괄표제부 `recap`)에는 단독주택(다가구) 등이 섞여 있다. `props.mainUse`로 나눠 쓴다(공동주택만 단지 집계에 넣을지 소비 쪽 결정).
- **byRegion 키는 원천마다 다르다**(품질 검사의 지역 비교는 원천 안에서만 이뤄진다):

| parcel, parcel_building, ledger_*, legal_* | 시도 코드 2자리 |
| store | 시도 코드 |
| bus_stop | 도시명 |
| park | 주소 첫 토큰 |
| applyhome | 원천의 `area_name` |
| move_in | 원천의 `지역` |
